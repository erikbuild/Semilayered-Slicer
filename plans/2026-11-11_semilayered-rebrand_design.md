# Semilayered Slicer: rebrand and automatic builds (design)

Date: 2026-11-11. Status: awaiting Erik's approval. The implementation plan follows in
`plans/2026-11-11_semilayered-rebrand.md` once this is approved.

## Intent

Unlayered 3D publishes the source of Unlayered Slicer (AGPL-3.0, a fork of OrcaSlicer) at
`github.com/Unlayered3D/Unlayered-Slicer`, but only lets people download built installers with an
Unlayered account. Erik wants installers anyone can download without an account.

`github.com/erikbuild/Semilayered-Slicer` is his public fork. It should build Windows, macOS and
Linux installers automatically on GitHub and publish them, under the name **Semilayered Slicer**,
and otherwise behave exactly like the upstream release it was built from, with one deliberate
exception: it never updates itself from Unlayered's servers.

## Terms

- **Upstream**: `Unlayered3D/Unlayered-Slicer`, git remote `upstream`. It publishes one commit per
  release ("Unlayered Slicer 0.1.10 source"), called a **source drop** here.
- **Product name**: "Unlayered Slicer" in any spelling (`UnlayeredSlicer`, `unlayered-slicer`,
  `Unlayered_Slicer`, `unlayeredslicer`, `Unlayered.Slicer`, all-caps forms).
- **Own files**: files that exist only in this fork (the rebrand tool, its tests, artwork sources,
  our workflow files, these plans).

## Goals

1. Every push to `main` (and a manual Run button) builds all platforms and publishes a public
   GitHub Release with the installers attached. No login needed to download.
2. The shipped application calls itself Semilayered Slicer everywhere a user can see: window
   title, menus, About, dialogs, tooltips, installer, shortcuts, macOS bundle, Linux desktop entry,
   file names, icon, splash and wordmark.
3. Semilayered Slicer has its own identity on the machine, so it installs beside an official
   Unlayered Slicer without either disturbing the other: own executable names, install location,
   settings folder, app ID `io.github.erikbuild.SemilayeredSlicer`, URL scheme and Windows file
   association ID.
4. Taking a new source drop is a mechanical step with no hand conflict resolution.
5. What changed is checkable by anyone: the tree on `main` can be regenerated from the upstream
   tree by running the rebrand tool, and a test proves the two match. Every difference from
   upstream that is not a rename is one entry in the tool's table of explicit edits, so that
   table is the complete list.
6. Semilayered Slicer never downloads or installs Unlayered's builds over itself.

## Non-goals (not now)

- Pointing the in-app updater at this fork's releases. The updater is switched off instead; see
  "Explicit edits".
- Support. Issues stay switched off on the fork; the build is provided as is.
- Nightly automatic sync from upstream. It needs a personal access token, because source drops
  change workflow files and the built-in Actions token may not push those.
- macOS signing and notarization, Windows code signing. The inherited pipeline already signs macOS
  builds when the repository variable `MACOS_SIGNING` and the Apple secrets are set, so this can be
  switched on later without code changes.
- Final artwork. A placeholder ships first.
- Removing or changing any other feature, including the account sign-in, usage diagnostics,
  printer firmware and configuration updates, and the Universe tab.

## Anti-goals (would make this a failure even if it builds)

- Breaking how the slicer talks to Unlayered printers, firmware, or services, or how it reads and
  writes project files shared with Unlayered Slicer and OrcaSlicer.
- Shipping something that claims to be made by, or endorsed by, Unlayered 3D.
- Removing or rewording upstream's copyright notices, licence text or legal documents.
- A rename kept as a hand-edited diff that conflicts with every source drop.
- A rename rule that silently stops applying when upstream rewords a line.

## Decided by Erik

- Full rebrand rather than a title-only change. The name is "Semilayered Slicer".
- App ID: `io.github.erikbuild.SemilayeredSlicer`.
- Claude draws placeholder artwork; real artwork can replace it later.
- Build on every push to `main` plus a manual button; publish a public GitHub Release.
- Run upstream's unmodified "Build all" once first as a baseline (started 2026-11-11, run
  43108415857).
- Behaviour stays as upstream's, except the updater.
- **The updater is switched off.** Upstream's updater, for someone signed in to an Unlayered
  account, downloads Unlayered's installer in the background and installs it when the app closes.
  That would silently turn an installed Semilayered Slicer into official Unlayered Slicer.
- **G-code keeps saying "generated by Unlayered Slicer".** Output stays byte-identical to
  upstream's, and both apps keep recognising each other's files.
- **Issues stay off.** The README and release notes say the build is unsupported and as is.
- **Publish what builds; block only on new failures** (decided after the baseline, below).
  Upstream's own 0.1.10 tree fails some of its own checks, and upstream's release workflow runs
  none of them. A checked-in list records the checks upstream's tree is known to fail for the
  current source drop. A release is published when every installer was built and nothing failed
  that is not on that list.
- **One fix to upstream's pipeline:** the Windows safety check looks for `OrcaSlicer.pdb`, a name
  this build never produces. The check and its test are edited to use the build's real name, so
  the check and the Windows unit tests run.
- **No Flatpak for now.** Upstream's Flatpak job cannot produce a bundle; it returns when they
  fix it.

## Baseline result (run 43108415857, upstream's unmodified 0.1.10 tree)

Built: macOS universal DMG, Linux AppImage (x86_64, aarch64), Windows installer and portable zip
(x64, arm64). Not built: Flatpak. The run finished red for four reasons, all defects in upstream's
tree and none caused by GitHub's runners:

| Failure | Cause |
|---|---|
| Windows build jobs, both architectures | `scripts/check_exception_throw_info.ps1` requires `OrcaSlicer.pdb`; the build produces `UnlayeredSlicer.pdb`. The step runs after the installers upload, so they exist, but the check never ran and the Windows unit-test jobs were skipped |
| Unit tests | "Nonplanar layers: hold back holds the safe part of a wall joined to a rim beside the top's highest point" and "Each cube's raft is its support, centered below it" fail on Linux x86_64, Linux aarch64 and macOS arm64. "release_targets_platform: other platforms only is not an update here" fails on Linux only |
| Slice check | 3 of 1326 slices fail, all "Unlayered 5 Axis Printer" (0.4, 0.6, 0.8 nozzle): no filament-change marker in the output |
| Flatpak, both architectures | The application links; the test build that CI adds then fails to link `slic3rutils_tests` (undefined `pango_fc_font_map_*`), so no bundle is produced |

These are the first entries of the known-failure list. Upstream's Windows release is compiled with
MSVC, while "Build all" compiles Windows with clang; the safety check above exists to catch a
known clang defect, which is why it should run on these builds.

## How it works

### The rebrand is a tool, not a diff

A rebrand tool in the repository turns an upstream tree into the Semilayered tree. The tree on
`main` is always exactly:

    rebrand(upstream source drop) + own files

Nobody edits upstream's files by hand. Taking a new source drop means replacing the tree with the
new upstream tree, restoring the own files, and running the tool again. The result is recorded as
a merge of the upstream commit, so history shows which drop each build came from. Erik makes every
commit; the tool stops before committing.

The tool does three kinds of work:

1. **Rename the product name** in file contents and in file and directory names, in every
   spelling. Nothing in the 0.1.10 tree wraps the name across two lines; if a later source drop
   does, the checks report it and nothing ships until the tool handles it.
2. **Apply a short table of explicit edits** for things a pattern cannot decide (listed below).
   Each entry names the file, the exact old text, the new text, and how many times it must match.
   If upstream changes that text, the tool fails and says which entry, instead of skipping it.
3. **Install the artwork**: put the Semilayered images where upstream's brand images were.

The tool is safe to run twice (the second run changes nothing).

### What is renamed and what is kept

Renamed: the product name, everywhere, including code identifiers, file names, build targets,
installer and artifact names, documentation, changelog and translations. This covers the settings
folder name, executable names, the Windows file-association ID, the single-instance message name
and the `unlayeredslicer://` URL scheme (it becomes `semilayeredslicer://`).

Kept exactly as upstream has it:

| Kept | Why |
|---|---|
| The bare word "Unlayered" (Unlayered 3D, Unlayered printers, "Sign in to Unlayered", Unlayered Universe, the "Unlayered" printer host type, printer profiles) | It names the company, its hardware and its services, which are still what the app talks to |
| Every `unlayered3d.com` address | Renaming them would point the app at a domain nobody controls |
| `github.com/Unlayered3D/RepRapFirmware` | The real firmware source |
| Wire and file-format identifiers: `X-Unlayered-*` headers, `unlayered-sys.json` and other names on the printer, firmware asset names and version tags, the `UnlayeredSlicer` metadata key in 3MF project files | Other programs and files depend on them |
| The generator name written into G-code and sliced project files ("generated by Unlayered Slicer 0.1.10"), and the code that recognises it | Erik's decision: output stays byte-identical to upstream's and both apps recognise each other's files. With the 3MF key above, these are the only places the product name itself stays |
| Environment variables and settings keys such as `UNLAYERED_NO_TELEMETRY` | Changing them would change behaviour for anyone who set them |
| Code identifiers that do not contain the product name (`UNLAYERED_VERSION`, `UNLAYERED_MOD`, `UnlayeredAccount`) | Invisible to users, and renaming them adds risk for nothing |
| Copyright notices, `LICENSE.txt`, the trademark statement, the privacy policy text (`PRIVACY.md` and the copy bundled in the app) | Legal text written by Unlayered 3D stays word for word |

### Explicit edits (the known ones; the plan enumerates the full list)

- **App ID**: `com.unlayered3d.UnlayeredSlicer` becomes `io.github.erikbuild.SemilayeredSlicer`
  (macOS bundle ID, Flatpak ID, desktop entry, metainfo, the profile-validator bundle ID).
- **Source links**: `github.com/Unlayered3D/Unlayered-Slicer` becomes
  `github.com/erikbuild/Semilayered-Slicer`, including the source address the app offers for the
  AGPL. The firmware repository link is not touched.
- **Attribution that the rename would make false**: the About text "Unlayered Slicer is developed
  by Unlayered 3D." becomes a sentence saying Semilayered Slicer is an unofficial build of
  Unlayered Slicer, which is developed by Unlayered 3D. Any other sentence the rename would turn
  into a false statement about who makes or supports the app gets the same treatment.
- **A modification notice** at the top of `README.md`: what this fork is, that it is not affiliated
  with Unlayered 3D, the date, and that the only change is the rename (AGPL section 5a asks for
  this).
- **The few sentences where bare "Unlayered" means the application**, for example "Unlayered asks
  before uploading any model".
- **Updater off** (the one behaviour change). Semilayered Slicer makes no request to the
  version-check address, at launch or from the menu, and never downloads or installs an update.
  Printer firmware and configuration updates are a different feature and are not touched.
- **Generator name pinned.** Today the G-code generator name comes from the same build setting as
  the application's display name. The places that write and recognise it are edited to use the
  upstream name directly, so renaming the application does not change them.
- **Windows safety check finds its PDB.** `OrcaSlicer.pdb` in
  `scripts/check_exception_throw_info.ps1` and its test becomes the name this build produces.

## Claude's calls (please check these while reading)

1. **Regenerate instead of merge.** Described above. The alternative, a normal `git merge` of each
   source drop, conflicts in hundreds of files every time.
2. **Separate settings folder.** Semilayered Slicer starts with fresh settings and does not read
   or write an installed Unlayered Slicer's. Someone moving over copies the folder by hand.
3. **`unlayeredslicer://` links will not open Semilayered Slicer.** Keeping the scheme would
   hijack it from an installed official copy.
4. **Publisher and vendor fields** (Windows installer vendor, Windows file properties "Company",
   Linux metainfo developer, MSIX publisher) say "Semilayered Slicer contributors", not
   "Unlayered 3D", because Unlayered 3D did not publish these binaries. Copyright lines are
   unaffected.
5. **Edited sentences appear in English in every language.** Where an explicit edit changes a
   translatable sentence, its translations no longer match it, so the app falls back to the
   English text.
6. **The changelog is renamed too.** It is shown in the app as release notes, so it has to match
   the name on screen. The README notice explains the history.
7. **Release naming.** Tag `semilayered-<upstream version>-b<build number>`, title "Semilayered
   Slicer <version> (build N)". The version inside the app stays upstream's, so it is clear which
   upstream release a build corresponds to. Upstream's own `v0.1.x` tags are left alone.
8. **Release contents.** Windows installer and portable zip (x64 and arm64), macOS universal DMG,
   Linux AppImage (x86_64 and aarch64), and a `SHA256SUMS` file. Not published: the MSIX package,
   debug symbols, the profile validator, test bundles. The release notes carry the "unofficial,
   not affiliated" statement, the upstream commit, the known-failure list as it stood for that
   build, and how to open an unsigned app on macOS.
9. **How the known-failure list works.** One text file among the own files, one line per failing
   check: the job, and for unit tests and the slice check the individual test or printer. The
   publish step reads the finished run, and refuses to publish if anything failed that is not
   listed or if an expected installer is missing. A listed check that now passes is reported so
   the list can be trimmed. When a rebranded run fails something unlisted, running "Build all" on
   the pristine upstream commit shows whose failure it is.
10. **Our CI lives in our own workflow files.** Upstream's workflows are only renamed. A push to
    `main` starts upstream's "Build all"; when that run completes, a second workflow collects its
    artifacts and publishes the release. Upstream's own release and publish workflows stay in the
    tree; they refuse to run outside Unlayered's repository.
11. **Tool language.** Python 3, standard library only, tests with `unittest`. That is how
    upstream's own repository tools are written.
12. **Where own files live.** `semilayered/` (tool, tests, artwork sources and generator),
    `plans/`, and `.github/workflows/semilayered_*.yml`.
13. **Dependencies rebuild once.** The rename touches comments in `deps/`, which changes the
    dependency cache key, so the first rebranded build rebuilds dependencies (a few hours,
    unattended). Excluding `deps/` would save that once and leave the old name in build output.
14. **"Check for Updates" opens this fork's releases page** in the browser instead of contacting
    Unlayered. A menu item that does nothing would look broken.
15. **Bug-report links point at the fork** even though Issues are off, because pointing them at
    Unlayered would send reports about an unofficial build to people who did not make it. The
    README notice says where things stand.
16. **If the inherited pipeline fails on GitHub-hosted runners**, work stops, the cause is found,
    and the options go to Erik. A fix to upstream's build or workflow files becomes an explicit
    edit only with his approval, one fix at a time.
17. **Artwork.** A simple original mark that does not resemble Unlayered's (theirs is a rounded
    square with a looping "un" stroke), plus the words "Semilayered Slicer" as text. Source SVGs
    are kept in the repository; a generator produces every size and format upstream's brand
    images come in, at the same pixel dimensions. Generated files are committed, so CI needs no
    image tools.

## How we know it is right

- **Unit tests** for the rename rules: every spelling, detection of a name wrapped across lines
  or joined by an unexpected separator, path renames,
  each kept item staying put, explicit edits failing loudly when their text is missing.
- **Integration tests** that run the tool on a small made-up tree in a temporary git repository,
  and checks on the real tree:
  - no product name left in any tracked text file or path except the listed exceptions;
  - every kept identifier occurs exactly as often after the rename as before;
  - a second run changes nothing;
  - no upstream brand image (compared by content) is left in the tree;
  - regenerating from `upstream/main` reproduces the committed tree exactly.
- **Upstream's own tests** (unit tests on five platforms, the slicing check, the Windows safety
  check) fail nothing on the rebranded tree beyond the known-failure list. The Windows unit tests
  have no baseline, because they were skipped in the baseline run; a failure there that is not
  one of the tests already failing on the other platforms is investigated before anything ships.
- **End to end**: a real push produces a real release. The installers are then downloaded without
  credentials, their checksums verified, and each one inspected for the new identity (bundle name
  and ID in the DMG, executable and product name in the Windows installer, desktop entry in the
  AppImage). The macOS build is launched on Erik's Mac.
- **The two decisions about behaviour**, checked on the built app: its executable holds no update
  check, and a file it slices still names Unlayered Slicer as its generator. A launch cannot show
  the first unattended, because a first launch stops at the setup wizard, so the log of a real
  first launch is read once, at the first release.

## Known consequences

- **Updates are manual.** Nothing tells a user a newer build exists. They download the next
  release from GitHub and install it over the old one.
- **Printers and files credit Unlayered Slicer.** The printer's touch panel and web interface show
  "Generated by Unlayered Slicer" for G-code that Semilayered Slicer produced, and anyone reading
  the file sees the same.
- **No support channel.** Issues are off, so the in-app bug-report link leads to a repository that
  takes no reports.
- **Unlayered's servers can tell.** The app's name appears in its HTTP User-Agent and in what it
  tells pages in the web tabs, so their site sees "Semilayered Slicer" and may treat it
  differently. Nothing here depends on that not happening.
- **Unsigned builds.** macOS blocks the app until the user allows it in System Settings; Windows
  shows a SmartScreen warning.
- **No bundled printer firmware.** Upstream's installer carries firmware images as an offline
  fallback, fetched by their private release workflow. "Build all" does not do that, so the app
  relies on the online firmware feed.
- **Trademark.** The remaining uses of "Unlayered" refer to Unlayered 3D's company, printers and
  services. That is the usual way a compatible third-party product refers to them. This is not
  legal advice.

## Risks

- The Windows safety check has never actually run on these builds. Once it can find its PDB it
  may fail for real, meaning the clang-built Windows binaries carry the defect it looks for. If
  so, work stops and the options go to Erik; building Windows with MSVC, as upstream's release
  does, is the fallback.
- Windows binaries are built with a different compiler from upstream's official Windows release.
- A workflow run started with the built-in token might not trigger the follow-on publish workflow.
  The fallback is one workflow that starts the build, waits for it, then publishes.
- Upstream can rename artifacts or restructure "Build all". The publish step checks for every
  expected file and fails with a clear message rather than publishing a partial release.
- A local macOS build before the first CI run would catch compile breaks in about an hour instead
  of several; whether to spend Erik's machine on that is his call at plan time.

## Left to the builder

Exact patterns and the full explicit-edit table, tool and command names, the placeholder's look,
which image tools the generator uses, workflow YAML details, release-notes wording, and the order
of commits. The plan sets these out for approval before anything is built.
